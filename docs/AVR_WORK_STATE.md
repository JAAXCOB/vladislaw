## Диагностика подтверждения MAX

В runtime-status.txt, checked_at_utc=2026-10-10T12:00:42Z, записаны 18 partner
upserts, 9 closes, 0 acknowledgements, 0 acknowledgement fallbacks и send failures,
9 sync request failures, 0 элементов sync queue и 8 записей Excel. Это сохранённая
диагностика; она не доказывает текущую серверную версию.

Путь подтверждения получения заявки системой: `sync_extracted_job` → `_post`
в `webhook/av_rescue_client.py` → `partner_order_sync.php` сайта → ответ
`ok=true, reply_required=true, reply_chat_id, reply_text` → MAX POST /messages.
Без точного boolean true отправка не выполняется. Нулевые counters требуют
проверить, запрашивает ли действующий сайт reply, и совпадает ли deployed code.

Путь взятия заявки водителем: Android `partnerAction` →
`api/partner_order_action.php`, action=claim. Обработчик сайта и
`partner_orders_helpers.php` отсутствуют в доступных деревьях. Не смешивать
«получена системой» и «взята водителем» и не отправлять подтверждение только
потому, что LLM увидела текст новой заявки.

Подтверждённый дефект бота: ошибка отправки MAX приводила к повтору upsert на
сайте; повторный ответ без reply_required мог потерять первоначальное сообщение.
Исправление подготовлено в отдельном MAX ack outbox. Ответ с текстом сохраняется
до отправки, повторяется фоновым worker даже без новых событий; есть retry,
dead letter и sent marker. Успех синхронизации сайта теперь отделён от доставки
MAX. Обнаружено и исправлено двойное экранирование регулярных выражений,
мешавшее разделять название сервиса и адрес точки Б.

Точность доставки — at least once. Сбой после принятия сообщения MAX, но до
сохранения локального sent marker может вызвать повтор. Не обещать exactly once.
Ключ подтверждения — source_id/event; редактирование заявки не создаёт новое
подтверждение. Ответ сайта должен адресовать исходный разрешённый чат.

## Локальные изменения

В main: запрет пустого/некорректного секрета и пустого токена; безопасная
проверка не-ASCII заголовка; секреты исключены из repr/текста ошибок; логи
сообщений приватны по умолчанию. Добавлена GET-only диагностика MAX и тесты.

В checkout ветки бота: отдельная очередь подтверждений и фоновый retry,
safe counters/health, проверка целевого чата, безопасная ошибка MAX без тела
ответа, plain fallback только для HTTP 400/404 при reply-ссылке; исправлены
regex точки Б. Добавлены диагностика и регрессионные тесты. Никаких реальных
сообщений, платежей и записей Excel оператора в ходе работы не выполнялось.

Ветка бота уже валидирует пустой webhook secret; изменение main не следует
выдавать за исправление этой проблемы на действующем Excel-сервере.

других сессий Work здесь не подтверждена. История текущей беседы не заменяет
серверные исходники. Поиск Pages/Spaces не нашёл материалов проекта; локальные
shared/library/.agents не содержали дополнительных материалов.

   существующий механизм инвентаризации. Не просить токены в переписке.
2. Проверить текущие SHAs сервера бота, systemd unit, env readiness без значений,
   ответ sync API и сохранённые source_id, права MAX и очередь сообщений.
3. Определить семантику требуемого «Заявка принята»: получение системой или
   взятие водителем. Сохранить правдивый текст и привязку к исходной заявке.
4. До любого push ветки бота изменить небезопасный автоматический deployment
   process: текущий workflow deploy-bot.yml запускается на push webhook/scripts.
   Сам workflow также восстанавливает Excel, меняет service/Caddy, выполняет
   reconciliation и регистрирует подписку. Его нельзя использовать как read-only
   диагностику или запускать ради получения доступа к журналам.
5. Подготовить ограниченный стендовый тест: site ack true → ошибка MAX →
   перезапуск → повтор доставки без повторного upsert; claim двумя водителями;
   неверный чат, повтор события, edit, возвращённая заявка, неполный ответ API.
6. Подключить операционную админку по [функциональному плану](AVR_ADMIN_FUNCTIONAL_SPEC.md).
   Финансовые риски main и отсутствие общего transactional writer остаются.
7. Найти Koda в доступном окружении/каталоге пользователя; не заменять его
   похожим сервисом и не утверждать подключение без проверенного инструмента.
